### 3. ffmpeg 包装器（核心技术，v1→v3）

**原理**：LuBot 每次播放都调用 `C:\Program Files\LuBot\core\runtime\ffmpeg.exe`。用 C# 写的包装器（10.7KB）替换它——解析命令行、改写、转发给备份的 `ffmpeg.orig.exe`，stdio 直通，LuBot 无感知。

- **v1**：注入真实摄像头 5% blend → 性能太差（17fps）废弃
- **v2**：优化（先裁9:16再放大+yuv混合）→ 恢复 29fps
- **v3（当前）**：**底层整体替换为 txt 脚本**——
  - 丢弃 LuBot 原生 CUDA 滤镜链，改跑 `2026.10.03最终版本地加素材循环.txt` 的完整去重滤镜链（noise/微缩放/微旋转/微裁剪/720×1280/eq/hue/setpts）
  - 真实摄像头 5% 叠加在 txt 链之上（透明度 `cam_opacity.txt`，默认 0.05）
  - **双输出**：分支A x264 fast 档 → `rtmp://127.0.0.1:1935/tklive`；分支B 1080×1920 bgr24 rawvideo → stdout 喂 TK Cam（虚拟相机不坏）
  - 性能结论：medium 档 0.82x 会积延迟，**fast 档实测 1.03x 实时**
  - 安全阀：启动前探测 :1935，MediaMTX 不在线自动回退 LuBot 原管线
- 日志 `%LOCALAPPDATA%\LuBot\wrapper.log`（每次播放记 `V3 TXT-pipeline applied`）
- **回滚**：把 `ffmpeg.orig.exe` 改回 `ffmpeg.exe` 即恢复原厂

### 6. 关键踩坑手册（都是实测换来的）

| 坑 | 解法 |
|---|---|
| bat 必须 CRLF 换行，LF 会被 cmd 解析成乱码命令 | 一律 python 写 CRLF |
| bat 含中文路径必须 GBK 编码或纯 ASCII | 含中文用 chcp 65001 或中转 ASCII 路径 |
| git-bash 把 `/f` `/nologo` 转成路径 | `MSYS_NO_PATHCONV=1` |
| Python 直传 dshow 设备名不能带引号 | `video=HP Wide Vision HD Camera`（无引号） |
| 双 dshow 实时源加 wallclock/genpts 会卡死同步(0.5fps) | 去掉，靠 fps=30 对齐时间轴 |
| yuva+colorchannelmixer 的 alpha 慢 | blend 同格式混合；先裁剪再 bilinear 放大 |
| TK Cam 只支持 1080×1920 输出、~26-29fps 硬上限 | 末尾 fps=30 补帧防延迟累积 |
| HLS 子列表直连 401 | 走 index.m3u8 |
| 60fps 源推流只有 0.46x | 素材统一转 30fps（keyint=120 按30fps设计） |
